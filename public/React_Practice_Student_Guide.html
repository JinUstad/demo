01

Props (Properties)

Concept: Props are the primary mechanism in React for passing data and callback functions downward from a Parent component to a Child component. Props are read-only (immutable).

WHY IS IT USED? (Key Takeaways):
  • Dynamic UI: Reusing a single component template to render varying student or product data.
  • Unidirectional Data Flow: Predictable Parent-to-Child flow prevents spaghetti state.
  • Event Callbacks: Enables children to notify parent components of user interactions.
// [WHY IS IT USED?]: Object destructuring provides direct variable access without 'props.name' // [WHY]: Default argument 'Student' prevents runtime rendering errors if parent omits role function StudentCard({ name = 'Student', course, isEnrolled, onNotify }) { return ( <div className="card p-3 shadow-sm"> {/* [WHY]: Dynamically displays data supplied by the parent */} <h4>{name}</h4> <p>Course: {course}</p> {/* [WHY]: Conditional rendering adjusts badge styling based on boolean status */} <span className={isEnrolled ? 'badge bg-success' : 'badge bg-secondary'}> {isEnrolled ? 'Active' : 'Offline'} </span> {/* [WHY]: Executes callback prop to inform parent of click event */} <button onClick={() => onNotify(name)}>Notify Parent</button> </div> ); }
02

Props Drilling & Context API Solution

Concept: Props Drilling happens when data must pass through intermediate components that do not actually consume the data, just to deliver it to a deeply nested child.

WHY IS IT CRITICAL TO UNDERSTAND?
  • The Problem: Intermediate components become cluttered with unnecessary props and maintenance overhead.
  • The Solution: For deep trees or global data (theme, user auth), use createContext() and useContext().
import { createContext, useContext, useState } from 'react'; // [WHY IS IT USED?]: Creates a global Context object for direct descendant consumption const ThemeContext = createContext(); function App() { const [theme, setTheme] = useState('dark'); return ( {/* [WHY]: Provider wraps tree, exposing value to all children without manual prop drilling */} <ThemeContext.Provider value={{ theme }}> <MiddleComponent /> </ThemeContext.Provider> ); } // [WHY CLEAN]: MiddleComponent receives zero unused props function MiddleComponent() { return <DeepChild />; } function DeepChild() { // [WHY IS IT USED?]: useContext directly retrieves theme from Provider const { theme } = useContext(ThemeContext); return <span>Active Theme: {theme}</span>; }
03

Form Handling in React

Concept: React forms manage user inputs via component state and intercept default submission with e.preventDefault() to retain SPA behavior.

WHY IS IT USED?
  • e.preventDefault(): Prevents full browser page reload so in-memory React state is preserved.
  • [e.target.name]: value: Single reusable change handler dynamically updates any field in state.
function StudentForm() { // [WHY IS IT USED?]: Single state object centralizes all input values const [formData, setFormData] = useState({ fullName: '', course: 'React' }); // [WHY IS IT USED?]: Dynamic key computation matches input name attribute const handleChange = (e) => { const { name, value } = e.target; // [WHY]: Spread operator (...) preserves untouched fields setFormData(prev => ({ ...prev, [name]: value })); }; const handleSubmit = (e) => { // [WHY]: Prevents page refresh (SPA architecture requirement) e.preventDefault(); console.log('Submitting payload:', formData); }; return ( <form onSubmit={handleSubmit}> <input name="fullName" value={formData.fullName} onChange={handleChange} /> <button type="submit">Register</button> </form> ); }
04

Form Validation

Concept: Validating input values on the client side ensures data integrity, prevents invalid network requests, and provides immediate visual feedback.

WHY IS IT USED?
  • Immediate Feedback: Guides user before submission without slow server round-trips.
  • onBlur Validation: Waits until user finishes entering data before flagging an error for better UX.
function ValidatedForm() { const [email, setEmail] = useState(''); // [WHY IS IT USED?]: Separate error state stores active validation error messages const [error, setError] = useState(''); const validateEmail = (val) => { // [WHY]: Regular expression checks for '@' symbol and valid domain const regex = /^\\S+@\\S+\\.\\S+$/; if (!val.trim()) return 'Email is required'; if (!regex.test(val)) return 'Invalid email format'; return ''; }; return ( <form onSubmit={(e) => { e.preventDefault(); setError(validateEmail(email)); }}> {/* [WHY]: Dynamic CSS class highlights border in red when invalid */} <input className={error ? 'border-danger' : 'border-success'} value={email} onChange={(e) => { setEmail(e.target.value); setError(''); }} onBlur={() => setError(validateEmail(email))} /> {/* [WHY]: Conditional rendering displays message only when error exists */} {error && <span style={{ color: 'red' }}>{error}</span>} <button type="submit">Submit</button> </form> ); }
05

Reusable Component (DRY Principle)

Concept: Building modular, generic components that can be used repeatedly with different props and children across an application.

WHY IS IT USED?
  • DRY Principle: Eliminates duplicate HTML and copy-pasted styling.
  • Central Maintenance: Updating 1 component file automatically updates every instance site-wide.
  • children Prop: Allows custom nested text, icons, and elements inside the component.
// [WHY IS IT USED?]: Configurable props (variant, size, children) enable universal reusability function CustomButton({ variant = 'primary', size = 'md', children, onClick }) { // [WHY]: Template literal dynamically creates class names const sizeClass = size === 'sm' ? 'btn-sm' : size === 'lg' ? 'btn-lg' : ''; return ( <button className={`btn btn-${variant} ${sizeClass} m-1`} onClick={onClick}> {/* [WHY]: children prop renders whatever text or icons the parent passes */} {children} </button> ); }
06

Controlled Component

Concept: A form input whose current value is governed by React State. Formula: value = {state} + onChange = {handler}.

WHY IS IT USED?
  • Single Source of Truth: Input element and React State are always in 100% synchronization.
  • Instant Transformation: Allows on-the-fly uppercase conversion, masking, or character limits.
  • Programmatic Reset: Simply calling setState('') clears the input without touching the DOM.
function ControlledDemo() { // [WHY IS IT USED?]: State is the authoritative Single Source of Truth const [text, setText] = useState(''); return ( <div> {/* [WHY]: value={text} locks the DOM value to React state */} {/* [WHY]: onChange transforms input to UPPERCASE in real time */} <input value={text} onChange={(e) => setText(e.target.value.toUpperCase())} placeholder="Type here..." /> <p>Live State: {text}</p> {/* [WHY]: Programmatic control clears input by resetting state */} <button onClick={() => setText('')}>Clear via State</button> </div> ); }
